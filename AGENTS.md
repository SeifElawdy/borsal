# Borsal — Codex Rules

## Communication
- - Always respond in concise English.
- Keep all explanations, summaries, and final reports in English.
- Final responses must not exceed 5 short lines unless requested.
- Be extremely brief. No long explanations or summaries.
- Final response: max 5 short lines covering changes, tests, and issues.
- Do not paste full files, diffs, or test logs unless requested.
- Report failures and blockers clearly.

## Token Efficiency
- Minimize token usage without sacrificing correctness.
- Inspect only files relevant to the current task.
- Use targeted searches instead of reading the entire repository.
- Avoid repeatedly reading unchanged files.
- Avoid unnecessary documentation and lengthy plans.
- Do not repeat previous explanations or completed work.
- Use concise tool outputs whenever possible.

## Development
- Backend MVP only. No frontend.
- Stack: Node.js, Express, MongoDB, CommonJS.
- Reuse existing code. Avoid unnecessary dependencies.
- Implement only the requested task.
- Write clean, minimal, maintainable code.
- Run relevant tests and report results briefly.
- Never modify or reset production data.
- Never commit or push unless requested.

## Workflow
- Execute tasks directly when requirements are clear.
- Ask questions only when genuinely blocked.
- Do not start the next phase without instructions.
- Keep responses short, but do not skip essential verification.
