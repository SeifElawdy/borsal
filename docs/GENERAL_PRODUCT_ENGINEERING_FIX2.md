## Root cause

The primary construction prompt explicitly prohibited cutting coordinates and offered only `TWO_PANEL_OPEN_SLEEVE`, `TWO_PANEL_SNAP_FLAP_POUCH`, or `UNSUPPORTED`. Its compiler implemented those two recipes. An unfamiliar product therefore could not be decomposed even when lower-level polygon, attachment and nesting capabilities existed. Legacy representation also requires missing physical material/grain/finished-size information: that must remain unresolved, rather than being fabricated to satisfy a schema.

## New pathway

The existing protected technical-generation route accepts strategy `ENGINEERING`; the normal Generate Product Design button uses it. Existing legacy/CANDIDATE/CONSTRUCTION routes remain compatible.

`borsal.engineering-plan/0.1` contains product name/function/closure, component purposes and quantities, proposed stitching shapes and allowances, materials required, ordered operations, creative changes and unresolved requirements. It contains no available-stock or verified-source declarations. The catalog/compiler is `src/services/productEngineering.js`; there is no product-name dispatch.

| Primitive | Required evidence and checks | Compiled output / limitations |
|---|---|---|
| RECT / POLYGON | Finite dimensions or explicit valid vertices; positive copies; explicit allowance | Existing polygon constructor, uniform convex miter offset; concave positive offsets remain unresolved |
| ELLIPSE | Explicit proposed width/height | 24-chord stitching polygon; approximation recorded; physical curve behavior unverified |
| SEAM | Two explicit copy/edge/direction paths and thread requirement | Existing seam-chain/reference checks and assembly representation; physical easing and strength unverified |
| ATTACH | Explicit copy/point references and thread | Existing anchor-containment checks; proposed point connection, no retention claim |
| INSTALL | Explicit required hardware/material and copy/point anchors | Existing material/reference/unit checks; no available stock or installation proof |
| FOLD | Existing HEM/BOX/PLEAT type, axis and allowance | Existing fold-axis containment; applies to all copies of that pattern; physical fold behavior unverified |
| FINISH | Component, contour-edge indices, OVERCAST method and thread | Checked references plus proposed instructions; physical fray control unverified |
| LAYER | Distinct ordered component copies, registration points and thread | Adjacent proposed point attachments; no volumetric layer simulation |

The host generates IDs, copies, allowance contours, exact polygon demand and explicit thread-estimate arithmetic. It passes these into the existing design candidate constructor, bridge, bounded nester, material/assembly checks and SVG renderer. It does not resize a failed design or introduce a second geometric validator.

The exact raw AI plan remains an immutable MODEL_OUTPUT version. Compilation appends a DERIVED version with plan, transformations, source/design hashes, instructions and checks. Missing material/grain/stock never prevents independent preliminary nesting, but keeps full readiness UNVERIFIED. Invalid references/polygons remain REJECTED. Unsupported operation names fail schema validation, rather than masquerading as implemented capabilities.

## Remaining boundaries

Elastic channels, gathering, weaving, buttonhole engineering, hook-and-loop installation, generic pins/clips and volumetric assembly are not implemented as validated operations. Those requirements must remain explicit unresolved items or rejected unsupported operations. Convex-offset geometry is not an allowance solution for arbitrary concave outlines. Chord approximations do not establish smooth-seam manufacturing accuracy. Proposed hardware and material specifications are requirements, never measured source properties or genuine inventory. Geometry fit and checked references do not establish function, strength or successful manufacture.
